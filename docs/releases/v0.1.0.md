# Hermes OmniRoute v0.1.0

This is the first public release of Hermes OmniRoute. It connects Hermes to your
OmniRoute gateway for chat, image generation, web search and reading web pages.
Your provider accounts and model routing stay in OmniRoute. Each Hermes profile
keeps its own gateway key and settings.

## What you can do

- **Choose models from OmniRoute in Hermes.** Use Auto or select a model from the
  gateway's current list. Hermes picks up context limits automatically. Image
  analysis and chat-title generation use the profile's gateway too.
- **Create Regular and Complex images.** Regular handles everyday image requests;
  Complex handles more detailed compositions, labels and edits. Reference images
  keep their original contents, and PNG, JPEG and WebP files are identified
  correctly even when their filenames have the wrong extension.
- **Search and read web pages through OmniRoute.** The gateway chooses among the
  search providers available to your key. Hermes keeps its page-address checks
  when reading and saving search results.
- **Keep profiles separate.** Each request uses the current profile's key and
  settings, including when switching between profiles on the same gateway.

## What's included

This repository installs two plugins. They have separate version numbers, so
seeing two different versions in Hermes is expected.

| Plugin | Version | What it adds |
| --- | --- | --- |
| `hermes-omniroute-provider` | 0.2.1 | Model selection, model lists and automatic context limits. |
| `hermes-omniroute-backend` | 0.2.3 | Image generation, web search and reading web pages. |

**v0.1.0** names this complete release. It does not change either plugin's version.

## Install

Run these commands as the user who owns the Hermes profile:

```sh
hermes plugins install 'echo-core/hermes-omniroute#model-provider' --enable
hermes plugins install 'echo-core/hermes-omniroute#backend' --enable
```

Set your OmniRoute gateway URL and the profile's `OMNIROUTE_API_KEY`, then select
OmniRoute in Hermes. See the [configuration guide](../../README.md#configure) for
setup and named-profile instructions. Hermes will still ask for any required
permissions or dependencies.

## Update an existing installation

Update each plugin in the profile where it is installed:

```sh
hermes plugins update hermes-omniroute-provider
hermes plugins update hermes-omniroute-backend
```

Restart the gateway after updating the model provider. Backend-only updates can
reload without a restart. Start a fresh chat when adopting new image instructions.

These commands follow the repository's stable `main` branch. Publishing a release
does not update an installation automatically. If you deliberately pinned an
installation to a commit, it stays there until you choose another commit. Hermes
0.23.1 requires the full commit SHA for `--ref`; release tag names are not accepted.
See [Updating](../../README.md#updating) for details.

## Compatibility and known limitations

- Tested with **Hermes 0.23.1** and **OmniRoute 3.8.54**. Your gateway key must allow
  the models, image tools and search services you want to use.
- Hermes 0.23.1 may incorrectly report a source mismatch for plugins installed
  from repository subfolders. The individual update commands above still work.
- The upstream image provider controls the final dimensions and file format.
  Accepting JPEG or WebP references does not guarantee output in those formats.
- With the example settings, Regular can try Complex once after a clear
  rate-limit rejection. Timeouts and uncertain failures do not trigger another
  generation automatically.
- The example keeps search on your gateway. Failed searches do not silently
  switch to a direct provider connection.
- Voice, video, screenshots and crawling entire websites are outside this release.

All 80 automated tests and 36 additional cases pass. Separate installation and
selected live checks have also been completed; this does not mean every provider
or client has been tested.
