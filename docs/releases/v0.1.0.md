# Hermes OmniRoute v0.1.0

First public release of the Hermes OmniRoute integration.

Use your OmniRoute gateway for Hermes chat models, image generation, web search
and page extraction. The gateway manages upstream accounts and routing, while
Hermes keeps each profile's configuration and credentials separate.

## Included plugins

| Plugin | Version | Purpose |
| --- | --- | --- |
| `hermes-omniroute-provider` | 0.2.1 | Model picker, live catalog, context discovery and native auxiliary endpoints. |
| `hermes-omniroute-backend` | 0.2.3 | Regular/Complex images, web search and page extraction. |

The repository release is **v0.1.0**. The two plugin versions are independent;
two entries in Hermes's plugin UI are expected.

## Highlights

- **Models through your gateway:** select OmniRoute models or Auto routes, load
  the live catalog and discover context limits automatically. Vision and title
  generation receive the current profile's configured gateway endpoint too.
- **Regular and Complex images:** use the native image tools with guidance that
  helps Hermes discover them when they are deferred behind tool search. Reference
  images keep their original bytes and get the correct PNG, JPEG or WebP upload
  type, even when their filenames have the wrong extension.
- **Gateway-selected search:** search and extract pages with the providers
  available to your gateway key. Extraction preserves URL provenance for Hermes's
  redirect checks and cache validation.
- **Profile isolation:** resolve credentials and configuration for the active
  profile, including when switching between profiles on the same gateway.

## Install and configure

Run as the user who owns the Hermes profile:

```sh
hermes plugins install 'echo-core/hermes-omniroute#model-provider' --enable
hermes plugins install 'echo-core/hermes-omniroute#backend' --enable
```

These ordinary Git installs use the repository source; they do not pin this
release. Set the profile's `OMNIROUTE_API_KEY` and gateway URL, then choose the
features you want. Follow the [README configuration guide](../../README.md#configure)
for the full example and named-profile instructions. Native dependency and
capability consent still applies.

## Updating

Existing unpinned installations keep their normal update behavior:

```sh
hermes plugins update hermes-omniroute-provider
hermes plugins update hermes-omniroute-backend
```

Publishing a release does not change those sources, enable automatic updates or
turn them into release-only subscriptions. Optional `--ref` installations require
an exact 40-character commit SHA and stay pinned until deliberately reinstalled
at another revision; a tag name is not accepted by Hermes 0.23.1's `--ref` option.

Restart the owning gateway after a model-provider update. Backend-only changes
support native reload. Start a fresh chat or use Hermes's native prompt refresh
when adopting new image-tool guidance in an existing conversation. See
[Updating](../../README.md#updating) for details.

## Compatibility and limits

- Tested with **Hermes 0.23.1** and **OmniRoute 3.8.54**. Gateway models and
  endpoints must be allowed by the selected profile's key.
- Hermes 0.23.1 can report drift for Git subdirectory installs even when named
  updates work. Model-provider changes require a gateway restart to refresh
  the loaded registry.
- Image geometry and output formats depend on the upstream provider. Correct
  reference upload types do not guarantee JPEG or WebP output.
- With the example configuration, Regular may try Complex once after a definite
  HTTP 429 rejection. Ambiguous failures and timeouts are not automatically retried.
- The example disables direct web rescue so failed gateway requests remain on
  the configured gateway path.
- Voice, video, screenshots and deep crawling are outside this release's scope.

The candidate source passes **74 offline tests and 22 subtests**, plus the frozen
prek checks. Native lifecycle and selected live integration checks are recorded
separately; this is not a claim that every upstream provider or client was tested.
